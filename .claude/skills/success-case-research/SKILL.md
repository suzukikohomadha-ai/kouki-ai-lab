# 他社成功事例リサーチ → クリエイティブ反映フロー

新規のチラシ・SNS・LP等のクリエイティブを作る前に、他社の集客成功事例を参考にしたい場合に使う。`market-research-protocol`（調査手順）・`fact-check-and-citations`（出典管理）の上位互換ではなく、その2つを土台にした「事例調査からクリエイティブまで」の橋渡し手順。

## 使うタイミング

**`canva-creative-production`の標準フローに組み込み済み（2026-07-28・社長の指示）。** チラシ・SNS投稿等のクリエイティブ制作では「言われたら使う」任意手順ではなく、目的確認の直後に毎回実施するデフォルト工程として扱う。以下のような単独リサーチ依頼でも同様に使う。

- 「他社の成功事例を調べて」等、クリエイティブ制作を伴わない単独のリサーチ依頼のとき
- `sales-proposal-production`・`sns-operation`・`official-line-design`等、他のクリエイティブ系Skillでも事例調査が要る場面（同じ7ステップを流用する）

## 標準フロー（2026-07-28新設）

1. **事例探索（リサ担当）**：`market-research-protocol`の情報源優先順位に従い、企業公式の事例ページ・プレスリリース・業界メディアのインタビュー記事・公的機関や業界団体の統計等、一次〜準一次情報から事例を探す。SNSの「バズった」という伝聞だけを唯一の根拠にしない
2. **事例の記録項目（リサ担当）**：会社名・事業内容・実施した施策の内容・成果（数値がある場合は出典を明記）・実施時期・情報源URL・発行主体・公開日/更新日・取得日・確度（一次情報／業界メディアの二次情報／伝聞）を記録する
3. **見つからない場合の扱い（リサ担当）**：`.claude/rules/evidence-policy.md`に従い、該当事例が見つからない場合は「今回確認した検索範囲では確認できませんでした」と明記し、断定・創作しない。個別事例の代わりに業界レポート等の一般的傾向を使う場合も、その旨と出典を明示する
4. **成功要因の分析（サトル担当）**：`satoru-growth-strategist.md`のマーケティングフレームワーク（STP・4P/4C・ファネル・KPI階層）を使い、事例を「なぜ効果が出たと考えられるか」に要因分解する。ここから先は`[確認済み事実]`（施策内容・結果として報道・公表されている事実）と`[推測・仮説]`（成功要因の解釈）を明確に分ける
5. **自社への翻訳（サトル担当）**：抽出した要因を、対象事業の状況・制約（予算・体制・ブランドトーン・KINOTOなら遺品整理等の配慮）に照らして「そのまま使えるか」「アレンジが必要か」を検討する。他社の結果が自社でも再現できると保証しない
6. **クリエイティブへの反映（カエデ担当）**：`canva-creative-production`のデザイン原則・`copywriting`のコピーの型と組み合わせて構成案・デザインに落とし込む。成果物内で他社の実名・実績を、自社の宣伝文句として誤認させる形で転用しない
7. **監査（アオイ・外部公開時）**：外部公開する成果物は`.claude/rules/external-publication-policy.md`に従い、事例として引用した内容と出典URLの中身が一致するかを含めてアオイが確認する

## 禁止事項

- 実在しない企業名・数値・「〇〇%改善」等の成功事例を創作しない
- 他社の事例をあたかも自社の実績であるかのように成果物に書かない
- 「真似すれば必ず成功する」等、再現性を保証する断定表現を使わない（`.claude/rules/evidence-policy.md`準拠）
- 特定の実在企業を批判的に評価する分析は、事実に基づく場合でも社外提出用の成果物には原則含めない（社内検討用メモに留める）
