# ルール：コンテンツ下書き自動化の共通規約

SNS・ブログ・LinkedIn等の「下書きを自動生成するクラウドルーティン」（RemoteTrigger）を新規作成・変更する際は、必ず本規約に従う。既存の該当ルーティンも本規約に統一済み（2026-07-29）。

## 1. 格納先

下書きは必ずNotionの「📝コンテンツ下書き・DB」（data_source_id: `67a53fa6-e7a5-451e-943a-d718ad723ae4`）に、1件＝1ページで登録する。汎用の📚ナレッジDB等には登録しない（下書きと調査レポート・監査ログは性質が異なるため混在させない）。

## 2. プロパティの設定

- **Name**：内容に即した自然なタイトル。事業名・媒体名の接頭辞（【KINOTO】等）は不要（別プロパティで管理されるため）。
- **事業**：`コホマダ` / `DKN` / `FP` のいずれか1つのみ設定可（この3つ以外の値は設定できない）。複数事業にまたがる内容は最も関連が深い事業を選び、決められない場合は `コホマダ` を選ぶ。本文冒頭で対象事業を明記すればよく、無理に事業を分けて複数ページにする必要はない。
- **媒体**：`note` / `X` / `Instagram` / `HPブログ` / `公式LINE` / `MEO` / `LinkedIn` のいずれか。新しい媒体を追加する場合は、まずこのDBの媒体selectプロパティに新しい選択肢を追加してから使う（未登録の値は設定できない）。
- **種別**：無料コンテンツは `無料`、価格を取る有料コンテンツは `有料`。
- **下書き作成済み**：ルーティンが1回の実行で本文まで完成させる場合は `__YES__`。note運用のように「まず候補だけ登録→後で本文を埋める」2段階フローの場合は、候補登録時 `__NO__`、本文完成時に `__YES__` へ更新。
- **マガジン**：note固有のプロパティ（貿易・海外展開／AI-DX導入／会社共通・その他）。note以外の媒体では未設定でよい。
- **価格（円）**：有料コンテンツのみ設定。それ以外は未設定。
- **投稿予定日**：分かっていれば設定、未定なら未設定。

## 3. 必須の免責文言（本文末尾）

> 本下書きは自動生成による候補です。実際の投稿・公開前に必ずaoi-quality-auditorの監査を経てください（external-publication-policy.md）。実際の投稿・公開は鈴木さん自身が行ってください。本エージェントは投稿・公開操作を一切行っていません。

## 4. ハルシネーション防止（evidence-policy.md と連動）

- 未確認の許認可・資格・料金・実績数値を断定的に書かない。
- 事業・媒体固有の制約（例：KINOTOの古物営業法・廃棄物処理法上の許可の有無自体に言及しない、FP技能士3級の資格境界）は、対象の事業・媒体に応じて必ずプロンプトに明記する。

## 5. 新規ルーティン作成時のチェックリスト

新しい「媒体の下書き自動生成」ルーティンを作る際は、設計前に必ず確認する。

- [ ] 対象の事業・媒体が実際に運用されているかを確認したか（HPが実在するか、SNSアカウントが実際に稼働しているか等。未確認のまま「運用中」と決めつけない。2026-07-29、KINOTOのHP未構築・MEO運用未確認のまま設計してしまい、後から一時停止した事例あり）
- [ ] 上記1〜3の規約（格納先・プロパティ・免責文言）に沿っているか
- [ ] 既存の同業務ルーティンと頻度・内容・cron時刻が重複／過密していないか
- [ ] `office/state.js` の `routines` 配列にも対応するエントリを追加・更新したか
- [ ] 新しい「媒体」が必要な場合、コンテンツ下書き・DBのselectオプションに先に追加したか
