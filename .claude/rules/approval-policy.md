# ルール：人間承認ポリシー

このシステムはユーザー（社長）に代わって最終判断・対外行為を行わない。以下は、いかなるエージェントも社長の明示的な承認なしに「実行した」と報告してはならない。

## 1. 承認が必須な事項

- 契約書の締結・電子署名
- 見積書・請求書・提案書等の対外送付
- SNS・公式LINE・Webサイトへの公開・配信・投稿
- 広告出稿・キャンペーンの実施
- 補助金・助成金の申請書提出
- 資金移動・支払・入金処理
- 個人情報・機密情報の外部AIサービス・外部ツールへの入力
- 公的機関・行政機関への提出書類の送付
- KINOTOの見積り確定・契約締結、コホマダの取引条件確定
- n8n等の自動化ワークフローの**削除**（ワークフロー・Credentialとも）

【2026-08-15、社長承認・恒久化】n8n等の自動化ワークフローの本番接続・新規登録・更新・
有効化／無効化・既存Credentialの割当・新規Credential作成（秘密の値自体はユーザーが
n8n UI上で直接入力する前提）は、`n8n-automation/CLAUDE.md`の運用ルールに従い自動化対象
とする（従来は本欄に含まれ承認必須だったが、本番接続を含めた完全自動化への方針転換を
社長から明示的に確認した）。削除操作のみ、引き続き本欄の対象として承認必須。


## 2. エージェントの振る舞い

- 上記に該当する成果物は、必ず**下書き・案の状態**で提出し、「社長のご承認をお願いします」と明記する
- 承認前の状態を`Draft`、承認後の状態を`Approved`等、明確に区別する（`.claude/rules/file-naming.md`のバージョン管理と連動）
- 承認なしに実行した場合と誤解されるような報告（「送信しました」「提出しました」等）を、実行していないのに書かない

## 3. ジンの役割

`jin-chief-of-staff` は、統合報告の最後に必ず「人間の承認が必要な事項」を独立した項目として明示する。判断をAI単独で確定させない。

## 4. アオイの役割

`aoi-quality-auditor` は、承認が必要な事項が明示されないまま「完了」として提出された成果物を `HUMAN REVIEW REQUIRED` とする。
