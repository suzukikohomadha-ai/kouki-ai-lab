# n8n-intake：業務ヒアリング

## 目的

新規の自動化依頼について、`templates/automation-intake.md` を使ってヒアリング結果を整理し、
「設計を止める情報」と「仮定で進められる情報」を分ける。

## 手順

1. `n8n-automation-lead` として、以下5領域を確認する（すでに分かっている情報は聞き直さない）。
   - **業務目的**：何を改善したいか／現在の問題／成功した状態／削減したい時間・コスト／
     ミスの発生箇所／自動化しない範囲
   - **現行フロー**：開始条件／担当者／使用ツール／処理手順／判断条件／承認者／
     例外処理／完了条件
   - **データ**：入力元・形式／出力先・形式／件数／欠損の可能性／個人情報・機密情報の有無／保存期間
   - **システム**：使用サービス／利用プラン／API利用可否／認証方式／管理者権限／
     サンドボックス／API制限
   - **運用**：実行頻度・時刻／許容遅延／障害時の通知先／手動復旧担当／保守担当／
     変更承認者／KPI
2. 重要度の低い不明点まで質問して作業を止めない。合理的な仮定を置ける項目は、
   仮定として明示し先へ進める。
3. `templates/automation-intake.md` の様式でヒアリング結果を保存する
   （`docs/` または案件ごとのフォルダに保存先を相談する）。
4. 「設計を止める情報（未確定のまま進めるとやり直しになる項目）」を明示し、
   ユーザーに確認を依頼する。

## 入力

自然文での依頼（例：「経理部の請求書処理を自動化したい」）

## 出力

`templates/automation-intake.md` の様式で埋めたヒアリング文書。
確認済み事実・現在の仮定・未確認事項（設計を止める情報）を分けて記載。

## 実行例

```text
/n8n-intake 経理部の請求書処理を自動化したい
```

## 次のフェーズ

ヒアリングが一通り埋まったら `n8n-design` へ進む。
