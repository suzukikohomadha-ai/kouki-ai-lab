# n8n-deploy：本番移行

## 目的

テスト合格済みのワークフローを本番のn8nへ登録・有効化する。
**この操作は毎回ユーザーの明示的な承認が必要**（`.claude/rules/security.md` 参照）。

## 事前チェックリスト（すべて揃うまで本番登録しない）

- [ ] 最終差分（ステージングと本番の設定差分）
- [ ] テスト結果（`tests/results/`、実際の出力つき）
- [ ] 未解決リスクの一覧
- [ ] バックアップ（既存ワークフローがある場合は更新前にエクスポート）
- [ ] ロールバック方法
- [ ] 監視方法（エラー通知先・ログ確認方法）
- [ ] 初回実行日時
- [ ] 担当者（業務責任者・技術責任者）
- [ ] ユーザーからの明示的な承認

## 手順

1. 上記チェックリストを `templates/deployment-checklist.md` に埋める。
2. ユーザーに提示し、承認を得る。
3. 承認後、本番環境へワークフローを登録する（Credentialは実在するものを割り当てる。
   推測で割り当てない）。
4. 登録直後は無効化した状態で内容を最終確認し、問題なければ有効化する。
5. `workflows/deployed/` に、デプロイ日時・担当者・バージョンを記録する
   （実データを含むエクスポートは `.gitignore` で除外済み）。
6. `templates/rollback-plan.md` にロールバック手順を明記する。

## 入力

`workflows/validated/*.json`、テスト結果、承認記録

## 出力

- `templates/deployment-checklist.md`（埋めたもの）
- `templates/rollback-plan.md`
- `workflows/deployed/` への記録

## 実行例

```text
/n8n-deploy ステージング環境へ登録
```

## 次のフェーズ

本番稼働後は `n8n-optimize` で運用状況を継続的に確認する。
