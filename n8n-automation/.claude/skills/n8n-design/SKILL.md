# n8n-design：要件定義・アーキテクチャ設計

## 目的

`n8n-intake` の結果をもとに、現行業務を可視化し、自動化可能性を評価した上で、
機能要件・非機能要件を定義し、最低2案（推奨案／低コスト案、必要に応じて高信頼性案）を
比較した設計書を作成する。

## 手順

1. `templates/current-process.md` で現行業務のフロー（開始条件〜完了条件、判断分岐、例外）を可視化する。
2. 自動化対象／自動化対象外を切り分け、ボトルネックとリスクを整理する。
3. `templates/requirements.md` に機能要件・非機能要件（セキュリティ・例外処理・承認・監視・運用）を整理する。
4. 未確認の技術仕様（ノード仕様・API仕様など）があれば `n8n-schema-researcher` に調査を依頼する
   （**推測で仕様を決めない**）。
5. `templates/workflow-design.md` に最低2案を作成し、次の項目で比較する。
   開発工数／月額費用／保守性／拡張性／安定性／セキュリティ／ベンダーロックイン／
   障害時の影響／必要スキル。
6. 各ワークフロー設計には、`.claude/rules/documentation.md` の「ワークフロードキュメントの必須項目」
   （名称・管理ID・目的・責任者・トリガー・入出力・Credential・実行頻度・エラー対応・
   ログ方針・監視項目・成功条件・KPI・ロールバック方法 等）をすべて埋める。

## 入力

`n8n-intake` の出力（ヒアリング文書）

## 出力

- `templates/current-process.md` を埋めた現行業務可視化
- `templates/requirements.md` を埋めた要件定義
- `templates/workflow-design.md` を埋めた設計書（2案以上の比較を含む）

## 実行例

```text
/n8n-design 顧客問い合わせの振り分けフローを設計
```

## 次のフェーズ

設計案がユーザーに承認されたら `n8n-build` へ進む。
