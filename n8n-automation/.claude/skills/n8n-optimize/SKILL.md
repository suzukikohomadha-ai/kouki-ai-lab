# n8n-optimize：運用改善

## 目的

本番稼働中のワークフローの実行結果（成功率・失敗率・実行時間・処理件数・再試行数・
APIエラー・LLMコスト・外部APIコスト・手動介入数・削減時間・障害内容）を分析し、
最適化案を `templates/optimization-report.md` にまとめる。

## 前提条件

n8nの実行ログ・実行履歴に、読み取り専用でアクセスできること（`[ユーザー入力待ち]` の場合は
先に確認する）。アクセスできない場合は、ユーザーから提供されたエクスポートやレポートを
分析対象とする。

## 手順

1. 対象期間の実行結果を取得する（実データが取得できない場合は、その旨を明記し
   仮の分析はしない）。
2. 成功率・失敗率・実行時間・コストを集計する。
3. 改善余地を、次の観点で洗い出す：不要ノード削減、API呼出回数削減、バッチサイズ調整、
   キャッシュ、重複排除、並列処理、サブワークフロー化、ログ量削減、実行データ保存期間、
   LLMモデルの見直し、プロンプト改善、フォールバック、SLA改善。
4. `templates/optimization-report.md` に、確認済み事実・改善案（影響・工数・リスク）・
   優先順位を記載する。
5. 本番設定の変更が必要な提案は、`n8n-deploy` の承認フローに乗せる（勝手に変更しない）。

## 入力

n8nの実行ログ／実行履歴（またはユーザー提供のエクスポート）

## 出力

`templates/optimization-report.md`（分析結果と改善提案）

## 実行例

```text
/n8n-optimize 過去30日分の実行結果を分析
```
