# セキュリティルール

## 必須チェック項目

新規・更新ワークフローは、本番登録前に以下を確認する（`n8n-quality-auditor` が担当）。

- APIキー・OAuthトークン・パスワードのハードコード
- 個人情報のログ出力・実行履歴への保存
- Webhookの認証・署名検証の有無
- 入力値のサニタイズ（不正ファイル・SSRF・任意コード実行・コマンドインジェクション・
  SQLインジェクション・プロンプトインジェクション）
- 過剰権限のCredential・Credential共有範囲
- テストデータへの実データ流用
- 外部AI（LLM API等）への機密情報送信
- データ保存地域・保持期間・削除手順

## AI Agent / LLMノードを含むワークフロー

- 外部入力（メール本文・フォーム入力・Webhookペイロード等）を**システム指示として扱わない**。
- 外部入力と内部指示（プロンプトの固定部分）を明確に分離する。
- 許可するツール・操作・データ範囲を明示的に制限する（ホワイトリスト方式）。
- プロンプトインジェクションを想定し、外部入力由来のテキストに含まれる指示文は
  実行対象ではなく「データ」として扱う旨をプロンプト内に明記する。

## Credential・シークレット

- `.env` はGit管理対象外（`.gitignore` で除外済み）。実値は `.env.example` に書かない。
- ワークフローJSONにCredentialの実値（トークン・パスワード・秘密鍵）を含めない。
  n8nは通常Credentialを別管理するため、JSON上は参照（名前・ID）のみになっているはずだが、
  `scripts/check-secrets.mjs` で機械的にも確認する。
- Credentialの実IDは推測で埋めず、`docs/` に「マッピング表（用途→実在するCredential名）」を
  作成し、実際の割り当てはユーザー承認のもとで行う。

## 権限の原則（最小権限）

- 読み取り専用でよい作業（調査・監査）は読み取り専用ツールのみを使う。
- 本番に影響する操作（登録・更新・有効化・削除・Credential操作・Git push・本番マージ・
  通知の本送信）は、`.claude/settings.json` の `permissions.ask` で毎回確認を必須にする。
- `bypassPermissions` 相当の設定、または承認を回避する仕組みは導入しない。

## 誤検知への配慮

`scripts/check-secrets.mjs` 等でシークレットらしき文字列を検出しても、**自動削除はしない**。
検出結果を一覧化し、人（ユーザーまたは監査担当）の判断を仰ぐ。
