# ドキュメント作成ルール

## 事実・仮定・提案の分離

すべての調査・設計結果は次の見出しで分ける。

- **確認済み事実**：実際に確認・実行・出典確認できたこと
- **現在の仮定**：確認できていないが、作業を進めるために置いた前提
- **未確認事項**：`[未確認]` `[要公式確認]` `[要インスタンス確認]` `[ユーザー入力待ち]`
  `[実行環境なしのため未テスト]` のいずれかを付けて列挙
- **推奨案／代替案**：複数案がある場合は最低2案を比較
- **判断理由**：なぜその案を推すか

「おそらく」「一般的には」という表現だけで仕様を確定しない。

## 実行結果の記録

コマンド・API・ワークフローを実際に実行していない場合、「実行済み」「正常に動作する」
「デプロイ完了」と表現しない。テスト・実行結果には必ず次を含める。

- 実行したコマンドまたは操作
- 実行日時
- 対象環境
- 入力データ
- 実際の出力
- 成否
- 残存リスク

## ワークフロードキュメントの必須項目

各ワークフローは最低限、次を定義する（`templates/workflow-design.md` に雛形あり）。

ワークフロー名、一意の管理ID、目的、業務責任者、技術責任者、対象部署、トリガー、
入力データ、出力データ、前提条件、利用サービス、必要Credential、実行頻度、想定件数、
最大件数、想定実行時間、許容遅延、エラー時の対応、手動対応への切替条件、ログ方針、
保存期間、個人情報の有無、監視項目、成功条件、KPI、ロールバック方法、変更履歴。
