# セキュリティ方針

このファイルは `.claude/rules/security.md`（CLAUDE.mdからimportされ、常に読み込まれる版）の
詳細解説版です。エージェントへの指示は `.claude/rules/security.md` を正としてください。

## 権限の3段階

| 段階 | 内容 | 設定場所 |
|---|---|---|
| 自動許可 | ファイル参照・検索・静的解析・JSON検証・テストファイル作成・ドキュメント作成・Git差分確認・読み取り専用API | `.claude/settings.json` の `permissions.allow` |
| 毎回承認 | ワークフロー登録/更新/有効化/削除、Credential操作、本番Webhook/環境変数変更、Git push、本番マージ、DB変更、外部書き込み、通知の本送信、有料APIの大量実行、個人情報処理、ファイル削除、システム設定変更 | `.claude/settings.json` の `permissions.ask` |
| 原則禁止 | シークレットのハードコード、`.env`のGit登録、認証情報を含むJSON保存、無断本番テスト、検証なし本番有効化、バックアップなし更新、出所不明なMCP/npm導入、未検証シェルスクリプト実行、無承認の破壊的変更、権限回避設定 | `.claude/settings.json` の `permissions.deny` ＋ 運用ルール |

## Hooksについて

現時点でHooksは**未実装・無効**です（`.claude/settings.json` の `hooks` は空）。
理由：動作未検証のHooksを有効化しない方針のため。技術的な権限制御を強化したい場合は、
以下の手順で安全に検証してから有効化してください。

1. サンプルHook（無害な処理：ログ出力のみ等）を1つだけ作成する
2. 実際にトリガーされることをログで確認する
3. 意図しない副作用（無限ループ、権限昇格、機密情報のログ出力）がないことを確認する
4. 問題なければ本番用のHookに差し替える

## AI Agent / LLMノードのプロンプトインジェクション対策

外部入力（Webhook・メール・フォーム等）は常に「データ」として扱い、
「指示」として解釈させない。システムプロンプト（固定の指示部分）と外部入力を
明確に分離し、実行可能なツール・操作範囲をホワイトリストで制限する。

## インシデント発生時

1. 該当ワークフローを無効化する
2. `templates/rollback-plan.md` に従いロールバックする
3. 影響範囲（処理済みデータ・重複実行の有無）を確認する
4. 原因を `docs/troubleshooting.md` の形式で記録する
5. 再発防止策を `n8n-quality-auditor` のチェック項目に追加する
