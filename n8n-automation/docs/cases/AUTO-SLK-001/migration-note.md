## 1. 合流の基本方針

`AUTO-SLK-003`は独立ワークフローではなく、`AUTO-SLK-001`に対する**スキーマ拡張・ルーティングロジック追加・Notion/Sheets書き込み拡張の集合**として設計されている（`AUTO-SLK-003/workflow-design.md`「位置づけ」節）。したがって合流とは、`AUTO-SLK-001`の実装が完了した後、そのノード構成に`AUTO-SLK-003`が定義するステップを追加することを指す。**フェーズ1本体を先に安定稼働させ、フェーズ1.5は運用実績を見てから追加する**（設計提案v5 2章「フェーズ1の実績を見てから」の方針をそのまま踏襲）。

## 3. 合流の前提条件（フェーズ1が満たすべきこと）

1. `AUTO-SLK-001`が本格運用段階（設計提案v5 3.5節・改善提案v2 3.5節の「3. 本格運用」）に到達していること。パイロット中の合流は、フェーズ1自体の品質評価とフェーズ1.5の品質評価が混ざり、Go/No-Go判断を誤らせるリスクがあるため避ける。
2. `AUTO-SLK-001`のUpsertロジック（案件キー・`event_id`重複排除）が安定稼働していること（改善提案v2 3.5節KPI：失敗率<10%、修正率<20%）。
3. 決定事項（📌・`AUTO-SLK-002`）の格納先（改善提案v2 Q4）が確定していること。未確定のまま合流すると、`AUTO-SLK-003/notion-properties.md`の「記録種別」に`決定事項`を含めない、という暫定判断の見直しが必要になる可能性がある。

## 4. 合流手順（案）

1. `AUTO-SLK-001`本体のワークフローJSONをエクスポートし、バックアップを取る（`n8n-automation/.claude/rules/security.md`「バックアップなしの既存ワークフロー更新」を原則禁止とするルールに従う）。
2. Notion UI上で`AUTO-SLK-003/notion-properties.md`の14項目を追加する。
3. Google Sheetsの新規タブ「取引先マスタ【自動登録・確認待ち】」を作成する（`AUTO-SLK-003/workflow-design.md`「4. 取引先マスタ連携」参照）。
4. `AUTO-SLK-001`のClaude抽出ノードが参照する`outputSchema`を`slk-extract v1.1`へ差し替える。
5. `AUTO-SLK-003/workflow-design.md`「ノード構成」節のステップ3〜7を、`AUTO-SLK-001`のUpsertノードの前後に追加する。
6. `validate-workflow.mjs`・`check-secrets.mjs`を実行し、結果を記録する。
7. ドライラン（Notion書き込みOFF）で新規ロジックのみを検証してから、パイロット運用へ進める。
