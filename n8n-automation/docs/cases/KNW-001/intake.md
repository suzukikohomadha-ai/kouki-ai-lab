# 業務自動化ヒアリングシート

- 案件名：n8n公式テンプレート自動収集・スプレッドシート整理ワークフロー
- ヒアリング日：2026-08-12
- ヒアリング担当（エージェント）：メイ（コウキAIラボ側で要件定義・設計を担当。実装フェーズでは`n8n-automation-lead`／エイトへ正式に引き継ぐ）
- 依頼者：鈴木さん（社長）

## 業務目的

- 何を改善したいか：n8n公式テンプレートギャラリー（`n8n.io/workflows`、2026-08-12時点で11,430件）の情報を手動で確認する手間をなくし、社内で検索・参照できるスプレッドシート形式のナレッジを自動的に整備する。
- 現在の問題：件数が多く（11,430件）、手動で網羅的に確認・整理することは非現実的。使えそうなテンプレートの見落としが発生しやすい。
- 成功した状態（Doneの定義）：新規作成したGoogleスプレッドシートに、全カテゴリのテンプレート情報（ID・タイトル・URL・カテゴリ・使用ノード一覧・AIによる特徴要約等）が整理され、毎週自動的に新規・更新テンプレートが差分反映される状態。
- 削減したい時間／コスト：手動でのテンプレート探索・内容確認・転記にかかる時間。
- ミスの発生箇所：手動転記時の抜け漏れ、情報が古いまま放置されること。
- 自動化しない範囲：取得したテンプレート情報の社外公開・商用転用（社長確定事項により社内ナレッジ限定。`.claude/rules/security.md`の外部AI送信・データ保存地域チェックの対象外にはならない点に留意）。実際にテンプレートを自社の業務へ採用するか否かの判断（AI要約はあくまで参考情報であり、採用判断は人が行う）。

## 現行フロー

- 開始条件：現状、体系的な自動収集フローは存在しない。手動でn8n.io/workflowsをブラウザ閲覧するのみ。
- 担当者：鈴木さん（手動確認時）
- 使用ツール：ブラウザ（`n8n.io/workflows`の検索UI）
- 処理手順：n8n.io/workflowsを検索・閲覧し、気になったテンプレートを個別に確認する。
- 判断条件：特になし（体系的な整理基準が存在しない）。
- 承認者：該当なし
- 例外処理：該当なし
- 完了条件：該当なし（継続的な収集の仕組みがそもそも存在しない）。

## データ

- 入力元／入力形式：`https://api.n8n.io/templates/search`（JSON。`workflows[]`に`id`/`name`/`description`/`nodes`/`user`/`createdAt`等を含む）、`https://api.n8n.io/templates/categories`（JSON。`id`/`name`/`displayName`/`icon`/`parent`）。いずれもリサが2026-08-12に実データ取得を確認済み（`logs/common_2026-08-12_n8n公式テンプレート取得手段調査_v1.md`）。
- 出力先／出力形式：新規作成するGoogleスプレッドシート（社長確定事項）。
- データ件数（想定）：初回バックフィル時、最大約11,430件相当（2026-08-12時点の`totalWorkflows`。実装着手時点では増減している可能性あり）。以後は週次の新規・更新分のみ。
- 欠損の可能性：`description`欄の書式（Markdown／HTML／プレーンテキストのいずれか）が`[未確認]`。テンプレート単位のカテゴリ情報をどのフィールドから取得できるか（`/templates/search`のレスポンスに直接含まれるのか、`/templates/categories`との突合が必要なのか）がリサの調査でも未検証で`[要追加調査]`。
- 個人情報の有無：あり。各テンプレートの`user`欄に投稿者名・ユーザー名・自己紹介・認証バッジ有無・アバターURル等が含まれる（Creator Hub上で本人が公開している情報ではあるが、スプレッドシートへの転記範囲は最小化する設計とする。詳細は`workflow-design.md`「投稿者個人情報の扱い」節）。
- 機密情報の有無：自社の機密情報は関与しない。ただし取得元API自体が非公式グレーゾーンという性質上の留意点がある（下記「システム」節参照）。
- 保存期間：`[要確認/社長]`（スプレッドシートの保存期間・削除方針は未確定）。

## 仮定で進められる情報（合理的な仮定を明示）
