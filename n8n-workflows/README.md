## インポート手順（n8n環境をお持ちの方向け）

1. n8nの画面右上メニュー → **Import from File** を選択し、上記いずれかの `.json` を読み込む（またはワークフロー一覧画面にファイルをドラッグ＆ドロップ）
2. インポート後、ワークフローは**必ず非アクティブ（`active: false`）のまま**です。すぐに有効化しない
3. 各ワークフローの **Gmailノード** を開き、Credential欄に実際のGmail OAuth2認証情報を新規作成・選択する（現在はプレースホルダーIDが入っており動作しません）
4. **HTTP Requestノード**（末尾、`disabled: true`）は、カスタム側の案件管理APIが未実装のため無効化されています。有効化・URL設定は本番のバックエンドAPIが確定してから行ってください
5. Webhookノードのテスト実行は、n8nの「Listen for Test Event」機能を使い、各JSON内に記載した「テスト用ダミーペイロード」（設計書 `T28...md` 参照）をPostmanやcurl等でPOSTして動作確認してください
6. 動作確認・パラメータの微調整（`typeVersion`や一部フィールド名は`[要インスタンス確認]`扱いです）が済むまで、本番接続・実際のメール送信は行わないでください

## 重要な注意事項

- **本番接続・Credential登録・ワークフローの有効化（Active化）は、必ず社長の承認を得てから行ってください。**
- これらはすべて**ダミーデータ・ダミートリガーで動くデモ用**です。実在のクライアントデータは一切含まれていません。
- ノードの`type`名はn8n公式ドキュメントで確認済みですが、`typeVersion`や一部パラメータの内部キー名は未検証の推定値です。インポート時にn8nが「新しいバージョンが必要です」等の警告を出す場合は、該当ノードを開いて手動で設定し直してください。
- メール送信基盤はGmail前提で作成しています。実際の送信基盤が異なる場合（Outlook・汎用SMTP等）は、Gmailノードを該当ノードに差し替える必要があります。
