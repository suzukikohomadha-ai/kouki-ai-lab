## 本文（下書き）

### はじめに

Claude Codeの開発者であるBoris Cherny氏（Anthropic）が、実践的な使い方のコツを30分で紹介するセッションを公開しています［出典：Mastering Claude Code in 30 minutes、Anthropic公式YouTube、https://www.youtube.com/watch?v=6eBSHbLKuN0］。今回はこの内容を私（鈴木）が実際に試しながら、日本語で要点を整理し、コホマダでのAI活用にどう落とし込めるかを解説します。

### 1. 導入直後にまずやるべきこと

登壇者は、Claude Codeを使い始めたら真っ先に以下を設定することを勧めています。

- ターミナルのセットアップ（Shift+Enterで改行できるようにする）
- テーマ設定（ライト／ダーク／色覚特性対応）
- GitHub Appの導入（GitHubのissueやPull RequestでClaudeにメンションできるようにする）
- よく許可するツールの事前許可設定（毎回の確認を減らす）
- （Macの場合）音声入力（ディクテーション）の活用。プロンプトを打たずに話しかけるだけで指示できる

[要ヒアリング：コホマダの開発環境でこれらの設定を実際に行うかどうかは、担当エンジニア側で確認が必要]

### 2. 使い始めの鉄則：まず「コードベースへの質問」から

Cherny氏が強調していたのが、いきなりコードを書かせるのではなく、**まず自分のコードベースについて質問する**ことから始める、という点です。Anthropic社内でも、新入社員のオンボーディングで最初にやらせているとのことです。動画04:53頃では、Claude Code導入前は技術系新入社員のオンボーディングに2〜3週間かかっていたのが、導入後は2〜3日に短縮された、という趣旨の話が紹介されていました（※文字起こしと照合し、要旨が一致することを確認済み。直接引用ではなく要旨紹介のため引用符は使用していません）。

これは単なるテキスト検索ではなく、コードの使われ方の実例を探したり、Gitの履歴を遡って「なぜこの関数は引数が15個もあるのか」といった経緯まで調べてくれる、という点がポイントです。GitHubのIssueを取得して文脈を補ったり、週次報告用に「今週何をコミットしたか」を自動でまとめさせる、といった使い方も紹介されていました。

**コホマダでの応用イメージ**：新しく参画するエンジニアや、他事業（KINOTO・FP）の担当者が技術的な引き継ぎを受ける際に、同じアプローチが使えそうです。

### 3. コード編集にステップアップする

質問に慣れてきたら、次はコードの編集です。ここでのコツは「いきなり大きな機能を丸投げしない」こと。まず設計や方針を考えさせ、承認を得てから実装に進ませる、という進め方が推奨されていました。特別なモードを使う必要はなく、「先にコードを書く前に計画を立てて」と伝えるだけでよい、という点は、特別なツール知識がなくても使える工夫として参考になります。

また、テストやスクリーンショットなど「自分の作業結果を確認する手段」を与えると、Claude自身が2〜3回繰り返し改善してくれる、という話も印象的でした。

### 4. チームのツールをつなぐ

自社で使っているCLIツールやMCPツールをClaude Codeに教えることで、既存の業務フローに組み込める、という話がありました。ツールの使い方（例：`--help`の内容）を伝えるだけで、Claude側が使い方を学習してくれるとのことです。

### 5. 「CLAUDE.md」でチームの知識を蓄積する

プロジェクトのルートに`CLAUDE.md`というファイルを置くと、セッション開始時に自動的に読み込まれる仕組みが紹介されていました。個人用・プロジェクト共有用・組織全体用と階層があり、よく使うコマンドやアーキテクチャ上の注意点などを書いておくことで、チーム全体の生産性が底上げされる、という考え方です（当ラボの`CLAUDE.md`もまさにこの仕組みを使っています）。

### 6. 覚えておくと便利な操作

- `Shift+Tab`：編集の自動承認モードへの切り替え
- `#`：気づいたことをその場で記憶させる
- `!`：ターミナルコマンドを直接実行するモード
- `Esc`：作業中でも安全に中断できる（2回押すと履歴を遡れる）
- セッションの再開（resume/continue）
- `Ctrl+R`：Claudeが見ている出力全体を表示

### 7. さらに進んだ使い方：SDKと並列実行

`-p`フラグを使ったCLI/SDK経由の利用や、CI・障害対応など自動化パイプラインへの組み込み事例が紹介されていました。上級者になると、複数のセッションを並列で走らせる（SSH・tmux・複数チェックアウト・git worktreeなど）運用も見られる、とのことです。

### 8. Q&Aセッションからの学び

質疑応答（動画24分頃〜）では、以下のような話がありました。

- 実装で特に苦労したのは「ターミナルコマンドの安全性」をどう担保するか（動画24:22頃。毎回確認を求めると使いづらく、かといって無条件許可も危険なため、権限を階層化する仕組みを作ったとのこと）
- 画像を使った指示（マルチモーダル）にも対応している（動画25:14頃）
- IDEではなくCLI（ターミナル）を選んだ理由は、社内で使うIDEが人によってバラバラだったことと、モデルの進化の速さを踏まえてUI層への過剰投資を避けたかったため（動画25:48頃）
- Anthropic社内の技術職の約8割が、日常的にClaude Codeを使っているとのこと（動画27:05頃）
