## 推測・仮説

- 「AIに何をやらせるか」を冒頭で明確に宣言する定型オープニングは、視聴者にとって「今回のお題」が一目で分かり、シリーズ間の乗り換え（競輪回しか見ない視聴者がMinecraft回も試しに見る等）を促しやすいと考えられるが、これは一般的な構成論からの仮説であり、実測データによる裏付けはない。
- サムネイルに「AIロゴ」等の共通ビジュアル要素を毎回置くことは、シリーズ全体の再認性（サムネイル一覧で「あのチャンネルだ」と分かること）を高めると推測されるが、クリック率への具体的な効果は未検証であり、`[推測・仮説]`にとどまる。
- 免責文言・非公式表記等のコンプライアンス要素をサムネイルに小さく入れることは、視認性とのトレードオフがあると考えられる（目立たせすぎると訴求力を削ぐ、小さすぎると実効性を欠く）。最適な配置・サイズは実際にテストしてみないと分からない。

## 分析

### 1. チャンネルコンセプト案

**一言コンセプト（案）**：「AIの判断に、人間が本気で乗っかってみたらどうなるか」を検証する体験型バラエティチャンネル。

**チャンネル名候補（3〜5案・実在チャンネル/ブランドとの重複は未確認）**

| # | 候補 | 意図 |
|---|---|---|
| 1 | AIにガチで任せてみた | 「やってみた」系の定番フォーマットを踏襲しつつ「ガチで」で本気度を強調。分かりやすさ優先 |
| 2 | AI社会実験室 | 「実験・検証」の客観性を前面に出す。的中率検証等の企画と相性が良い |
| 3 | まるっとAI任せ | 予想・生成・プラン作成まで"まるごと"AIに委ねる企画特性をひと言で表現 |
| 4 | AI検証部 | 「部活動」的な継続性・チーム感を出し、シリーズ化・視聴者参加企画（お題募集）と相性が良い |
| 5 | 全部AIに聞いてみた | 口語的で親しみやすく、複数企画（予想・生成・プラン）を「聞いてみた」で統一しやすい |

**想定ターゲット層**（サトルのSTP整理と整合）：
- 主軸：AI・生成AIに関心があるテック系視聴者、「やってみた」系バラエティ全般の視聴者
- 副次：ゲーム実況・Minecraft好き（企画②）、公営競技・予想バラエティ好き（企画①）、旅行VLOG・体験共感層（企画③）

### 2. 3企画の初期構成案

各企画とも `video-script-production` の基本型（フック→課題提示→解決→証拠→CTA）を、サトルが設計した「宣言→過程→結果→次回予告」の枠組みに合わせて翻訳した。

#### 企画①：AI競輪予想検証

**(a) 基本構成**

| パート | 内容 |
|---|---|
| オープニング（0:00〜） | シリーズ共通OP＋「今日のお題：AIに◯◯競輪場のレースを予想してもらう」を宣言。対象レースの基本情報を人間パートが紹介 |
| 本編：AIへの依頼 | AIへのプロンプト投入・予想生成の過程を画面共有でそのまま見せる（透明性・誠実性の担保） |
| 本編：解説 | AIに予想理由を語らせる、または演者が要約して紹介 |
| **免責表示（毎回・固定位置）** | 画面下部テロップ＋概要欄に「本企画は投票を推奨・勧誘するものではなく、AIの予測精度を検証するエンターテインメント企画です。車券の購入は20歳以上の方がご自身の判断で行ってください」を明記。投票サイトへの誘導リンク・購入代行の演出は行わない（リョウの法務論点整理「代替案」節に基づく） |
| 本編：観戦 | レース結果の紹介（実況・映像） |
| 検証／オチ | 的中／不的中を淡々と答え合わせ。外れた回も編集でカットせず、累計的中率をシリーズ通して開示 |
| CTA | 次回予告＋チャンネル登録・コメントでのお題（対象競輪場）募集 |

**(b) タイトルの型（3〜5パターン・断定表現なし）**

- 「AIに競輪予想させてみた結果…【第◯回】」
- 「AI vs 人間予想、的中率はどっちが上？（◯月◯日開催）」
- 「AIの競輪予想、当たるのか外れるのか検証してみた」
- 「【検証】AIに◯◯競輪を予想させたら」
- 「AI予想の累計的中率、今どれくらい？」

※「必ず当たる」「絶対」「儲かる」「必勝」等の断定・煽り表現は使用しない（`copywriting`禁止事項・リョウの法務論点整理に基づく）。

**(c) サムネイルの方向性**

- 構図：レース結果を見た瞬間の演者のリアクション（驚き・困惑どちらも可）＋AI画面キャプチャの一部を切り取って配置
- 文字要素：シリーズ共通の「AI予想」ロゴマークを毎回同じ位置に配置。「当たった？外れた？」等の疑問形で興味を引く（結果を誇張・先出ししない）。的中率の数字を載せる場合は、動画内容と一致する実測値のみを使う
- コンプライアンス要素：サムネイル隅に小さく「エンタメ検証企画」等の注記アイコンを置く案（視認性とのバランスは実制作時に要検討）
- 色調：AI要素は近未来的な寒色系（ブルー／グリーン）、競輪要素はスピード感のある斜めライン・暖色差し色

#### 企画②：AI生成Minecraftワールド実況

**(a) 基本構成**

| パート | 内容 |
|---|---|
| オープニング | シリーズ共通OP＋今回のお題発表（例：「AIに"絶対に住みたくない家"を作らせてみた」） |
| 本編：生成 | AIへのプロンプト入力・ワールド生成過程をタイムラプス／早送りで見せる |
| 本編：初見リアクション | 生成されたワールドを初めて見た演者の反応 |
| 本編：プレイ | ワールド探索・生活・攻略パート。カメラマン視点の切り替えを活用 |
| 検証／オチ | お題の達成度合いを演者が採点・総括。ハプニングや想定外の生成結果を隠さず見せる |
| CTA | 次回のお題を視聴者から募集＋チャンネル登録 |
| **表記（固定・毎回）** | 動画内または概要欄に「本チャンネルはMojang/Microsoft社の公式チャンネルではありません」等の非公式表記を明記する運用とする（サトルの整理に基づく仮運用。Minecraft利用ガイドライン原文の直接確認は未了のため、確定文言は追加確認後に決定） |

**(b) タイトルの型**

- 「AIに"◯◯な世界"を作らせてみたら、とんでもないことになった」
- 「【検証】AI生成ワールドで24時間生き延びられるか」
- 「AIが考えたマイクラの家、住み心地は？」
- 「視聴者のお題をAIに丸投げしてマイクラワールド作ってみた」
- 「AI vs 人間、変な建築対決」

**(c) サムネイルの方向性**

- 構図：生成ワールドの奇抜なビジュアル（引きの絵）＋演者の驚き顔インセット
- 文字要素：お題キーワードを大きく表示（例：「灼熱の家」）＋シリーズ共通ロゴ
- 色調：Minecraft的な鮮やかな配色を活かしつつ、シリーズ共通のAIロゴ・フレームで統一感を出す

#### 企画③：AI旅行プラン実行

**(a) 基本構成**

| パート | 内容 |
|---|---|
| オープニング | シリーズ共通OP＋「今回は行き先も予定も全部AIに決めてもらいます」を宣言。予算・日数等の条件をAIに伝える様子を見せる |
| 本編：プラン作成 | AIへの依頼過程（条件入力→プラン生成）を画面共有・要約で紹介 |
| 本編：プラン発表 | 行き先・日程・予算等の生成プランをテロップで紹介 |
| 本編：実行 | 実際の旅行実行パート（VLOG形式。移動・宿泊・食事等） |
| 検証／オチ | AIプラン通りにいかなかった場面（現地のリアル・ハプニング）を隠さず見せたうえで、演者が満足度・費用対効果を総括評価 |
| CTA | 次回の行き先リクエストをコメントで募集＋チャンネル登録 |

**(b) タイトルの型**

- 「AIが決めた旅行プランで◯泊◯日、行ってみた」
- 「予算◯万円、AIに旅行を丸ごと任せてみた結果」
- 「【検証】AIプランは"当たり"か"ハズレ"か（◯◯旅行編）」
- 「AIにしかできない旅行プラン、本当に良かった？」
- 「行き先も宿もAI任せにしたら、まさかの展開に」

**(c) サムネイルの方向性**

- 構図：現地の象徴的な風景・カット＋演者の表情（満足・困惑どちらもシリーズの魅力として使える）
- 文字要素：行き先名＋「AIプラン」ロゴ。予算等の具体的な数字を使う場合は事実に基づくもののみ（誇張しない）
- 色調：旅先の実写を活かしつつ、シリーズ共通のAIロゴのトーンで統一

### 3. シリーズ化・ブランディングの一貫性

3企画を「バラバラな個別企画」ではなく「AIにやらせてみたシリーズ」として一体に見せるための方針。

- **統一OP**：3企画共通のオープニングテンプレートを用意する。AIとのチャットのふきだしが表示されるアニメーション等、「AIに問いかける」演出を毎回の入口に固定し、ナレーション／テロップで毎回同じ導入フレーズ（例：「今日もAIに、本気でやらせてみます。」）を使う。
- **マスターロゴ＋サブロゴ**：チャンネル全体のマスターロゴ（AIを想起させるアイコン＋ワードマーク）を固定し、企画ごとにサブアイコン（競輪＝速度線、Minecraft＝ブロック、旅行＝地図ピン等）を差し替えて使う。サムネイル・OPテロップ双方で同じロゴセットを使う。
- **定型フォーマット**：各動画冒頭に「AIに何をやらせるか」を宣言する定型カット、終盤に「検証結果」を一言でまとめるテロップを固定フォーマットとして毎回入れる。免責・非公式表記が必要な企画は、毎回同じ位置・同じ文言のテンプレートとして表示する（企画ごとに文言や有無がバラつくと視聴者の信頼を損ないやすいため）。
- **配色・フォント**：チャンネル全体のキーカラー（例：ダークネイビー＋差し色の蛍光グリーン等、AIらしさを演出する2色）を固定し、企画ごとのサブカラー（競輪＝赤系、Minecraft＝緑系、旅行＝水色系）をアクセントとして使い分ける。見出し用フォントを1種に統一し、サムネイル一覧での再認性を高める。
- **通し番号によるシリーズ化**：各企画に「AI予想 #12」のように通し番号を振り、単発ではなくシリーズとしての継続性を可視化する（サトルのフェーズ設計・KPI階層とも整合）。

2. **競輪企画の法務リスク（リョウの整理を踏まえた対応中・最終GOは弁護士確認待ち）**：本ファイルの構成案には投票誘導なし・免責文言明記・断定表現回避を組み込んだが、これはリスクを下げる設計であって適法性を保証するものではない。リョウの報告のとおり、公開前に人間の弁護士へのスポット相談が必要（`logs/..._競輪予想企画_法務論点整理_v1.md`「推奨案」節）。
3. **Minecraft利用ガイドラインの原文未確認**：非公式表記・収益化条件（物販上限等）はサトルの整理（二次情報ベース、原文未到達）に基づく仮運用。確定文言は原文確認後に見直しが必要。
4. **AI生成コンテンツの収益化ポリシー・誠実性リスク**：リサの調査（2025年7月のYouTube「inauthentic content」規定改定）が指摘するとおり、AI生成素材への依存度が高すぎる構成は収益化除外リスクになりうる。本ファイルの構成案は「AIの過程を見せる＋人間の検証・リアクションを明確な付加価値にする」設計だが、実際の編集段階でもこの比重を意識する必要がある。
5. **サムネイル・タイトルの誇張リスク**：クリック率を意識するあまり、的中率・費用対効果等の数値を誇張したり、結果を先出しして誤解を招く表現（クリックベイト）にならないよう、`copywriting`の禁止事項（誇大・断定表現の回避）を毎回確認する。
6. **本ファイルは初期ブラッシュアップ段階**：タイトル・サムネイル文言・免責文言の最終文面が確定した段階で、`external-publication-policy.md`に従い**必ずアオイの監査を経る**。また、実際の投稿・公開操作は社長自身が行う（`.claude/rules/approval-policy.md`）。
