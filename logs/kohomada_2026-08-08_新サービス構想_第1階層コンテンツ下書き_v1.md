#### 記事1：Claude Codeとは何か、実務者が触ってみる理由

「Claude Code」という名前を初めて聞いたとき、多くの方が「エンジニア向けのツールでは」と感じると思います。実際、Claude Codeは元々、ソフトウェア開発者がコードを書いたり直したりする作業を助けるためにAnthropic社が提供しているツールです［確認済み事実：Claude Codeは、コードベースを読み取り、ファイルを編集し、コマンドを実行し、開発ツールと連携するエージェント型のAIツールと公式に説明されています。ターミナル・IDE拡張・デスクトップアプリ・Webの複数の場所で使えます（出典：Anthropic公式ドキュメント、確認日2026-08-11）］。

では、なぜ貿易・海外展開支援の実務をしている私が、このマガジンでClaude Codeを取り上げているのか。理由は単純で、私自身が自分の実務（AIエージェントチームの構築・運用）のためにこのツールを使っているからです。

Claude Codeの中身を分解すると、やっていることは大きく分けて3つです。

1. 指示を自然な言葉で受け取る
2. 手元のファイル（フォルダの中身）を読んだり書いたりする
3. 必要に応じて、決められた手順（コマンド）を実行する

この3つは「コードを書く」という用途に限った話ではありません。フォルダの中に置いた資料を読ませて要約させる、下書きを作らせる、繰り返し使う確認項目をチェックさせる——といった、貿易実務でもよくある「情報を整理する」「文章を作る」作業にも、同じ仕組みがそのまま使えます［仮定：この応用可能性はAnthropic公式が明示的に推奨しているものではなく、実務者としての私の使い方に基づく整理です］。

もちろん、Claude Codeは万能ではありません。指示が曖昧だと期待と違う結果になりますし、最初は操作に戸惑う場面もあります。「触れば必ず業務が効率化する」というような保証はできませんし、そのような約束はしません。ただ、「難しそうだから」と敬遠して触らずにいるのは、少しもったいないと感じています。

このマガジンの第1階層では、貿易・海外展開の実務者の方が、Claude Codeを実際に手元で動かせるようになるところまでを、順を追って案内します。次回は、インストールとアカウント作成からです。

#### 記事2：インストールとアカウント作成

前回、Claude Codeがどんなツールかをざっくり紹介しました。今回は実際に手元のパソコンで動かせる状態にするところまでを進めます。

**動作環境を確認する**

Claude Codeは以下の環境で動作するとされています［確認済み事実、出典：Anthropic公式ドキュメント、確認日2026-08-11］。

- OS：macOS 13.0以降／Windows 10（バージョン1809以降）またはWindows Server 2019以降／Ubuntu 20.04以降 など
- ハードウェア：4GB以上のRAM
- ネットワーク：インターネット接続が必須
- シェル：Bash・Zsh・PowerShell・CMDのいずれか

一般的な業務用パソコン（数年以内に購入したWindows／Mac）であれば、条件を満たしていることがほとんどです。不安な場合はお使いのパソコンのメーカーサイト等でOSのバージョンを確認してください。

**アカウントを用意する**

ここが実務者にとって最初のつまずきポイントになりやすい部分です。Claude Codeを使うには、Claudeの有料サブスクリプション（Pro／Max／Team／Enterpriseのいずれか）、またはClaude Consoleアカウントが必要です［確認済み事実、出典：同上、確認日2026-08-11］。**無料のClaude.aiアカウントだけでは、Claude Codeは利用できません。** まずお使いになりたいプランを、Anthropic公式サイトの料金ページで確認してください。

**インストールする**

インストール方法は複数用意されていますが、公式が「推奨」としているのは、以下のコマンドをターミナル（Windowsの場合はPowerShellまたはコマンドプロンプト）に入力する方法です［確認済み事実、出典：同上、確認日2026-08-11］。

- Mac／Linux：`curl -fsSL https://claude.ai/install.sh | bash`

「ターミナルって何？」という方は、まずお使いのOSで「ターミナル」（Mac）または「PowerShell」（Windows）を開くところから始めてください。開き方が分からない場合は、お使いのOS名＋「ターミナル 開き方」等で検索するか、公式サイトの案内も参照してください。

バージョン番号が表示されれば成功です。

インストールが終わったら、フォルダの中で`claude`と入力して実行すると、初回はブラウザでのログインを求められます［確認済み事実、出典：同上、確認日2026-08-11］。案内に従ってログインすれば準備完了です。

#### 記事3：最初のプロジェクトを作ってみる

インストールとログインが終わったら、いよいよ実際に動かしてみましょう。難しいことは何もありません。まずはフォルダを1つ用意するだけです。

**手順**

1. パソコンの好きな場所に、空のフォルダを1つ作ります（例：「claude-test」）。実際の業務データを入れる前に、まずは練習用のフォルダで試すことをおすすめします。
2. ターミナル（PowerShell）でそのフォルダに移動します。
3. `claude`と入力して実行します。対話セッションが始まります［確認済み事実、出典：Anthropic公式ドキュメント、確認日2026-08-11］。

**最初の指示を出してみる**

セッションが始まったら、日本語でそのまま話しかけるように指示や質問を打ち込みます。公式のガイドでは、まず質問から始めることが勧められています［確認済み事実、出典：同上］。例えば、フォルダの中に何かファイル（メモ・資料等）を入れてから、次のように聞いてみてください。

- 「このフォルダに何が入っているか教えて」
- 「この中身を簡単に要約して」

Claude Codeはフォルダの中を自動的に確認しに行くため、いちいち「このファイルを読んで」と指定しなくても、必要な範囲を自分で探しにいきます［確認済み事実：「プロジェクトファイルは必要に応じて読み込まれ、手動でコンテキストを追加する必要はない」と公式に明記されています。出典：同上、確認日2026-08-11］。

**ファイルを作らせてみる**

慣れてきたら、「この内容を1枚のメモにまとめて、summary.txtというファイルに保存して」のように、ファイルの作成・変更を伴う指示も試してみましょう。この場合、Claude Codeは変更内容を提案し、実行前に確認を求めてきます（初期設定の挙動。設定によって挙動を変えることも可能です）［確認済み事実、出典：同上、確認日2026-08-11］。「いきなり書き換えられてしまうのでは」という不安を持たれる方もいますが、既定では必ず一度立ち止まって確認が入る仕組みになっています。

ここまでできれば、Claude Codeを実際に「使えた」という最初の一歩です。「思っていたより難しくなかった」と感じる方もいれば、「思うように伝わらなかった」と感じる方もいると思います。どちらも自然なことです。次回は、指示の出し方とファイルの読み書きの基本を、もう少し詳しく見ていきます。

#### 記事4：基本操作：指示の出し方・ファイルの読み書き

前回、実際にフォルダを用意してClaude Codeを動かしてみました。今回は、日々の操作でよく使う「指示の出し方」と「ファイルの読み書き」の基本をまとめます。

**指示は自然な言葉でよい**

Claude Codeへの指示は、プログラムのコマンドのような特別な書き方をする必要はなく、話しかけるような自然な日本語で問題ありません。ただし、指示が具体的であるほど、狙った結果に近づきやすくなります。公式のガイドでも「曖昧な依頼より具体的な依頼のほうがよい」ことが例とともに紹介されています［確認済み事実、出典：Anthropic公式ドキュメント、確認日2026-08-11］。例えば、

- 曖昧な例：「直しておいて」
- 具体的な例：「この資料の日付表記を、すべて西暦に統一して」

のように、「何を」「どうしてほしいか」をなるべく具体的に伝えると、やり直しの回数を減らせます［仮定：この効果の度合いは実務での使用感によるため断定はしません］。

**ファイルを読ませる**

Claude Codeは、作業しているフォルダの中身を必要に応じて自動的に読みに行きます。「このフォルダの中の◯◯というファイルを読んで、要点をまとめて」のように、特定のファイルを指定して聞くこともできます。

**ファイルを書かせる・直させる**

新しいファイルを作らせたり、既存のファイルを直させたりすることもできます。既定の設定では、ファイルを実際に変更する前に、Claude Codeが変更内容を提案し、こちらの承認を求めてきます［確認済み事実、出典：同上、確認日2026-08-11。承認を求めるかどうかは「許可モード」の設定によって変わり、`Shift+Tab`キーでモードを切り替えられます］。慣れないうちは、この確認が入る初期設定のまま使うことをおすすめします。

**よく使う言い回しの例（一般化した例）**

- 「この資料を要約して」
- 「この文章のたたき台を作って」
- 「このフォルダの構成を教えて」
- 「さっき作った内容を、◯◯というファイル名で保存して」

**セッション中に使える簡単なコマンド**

Claude Codeの対話セッション中は、`/`から始まる特別なコマンドも使えます。よく使うものとして、会話履歴をクリアする`/clear`、使えるコマンド一覧を表示する`/help`、セッションを終了する`/exit`があります［確認済み事実、出典：同上、確認日2026-08-11］。

まずはこの範囲の操作に慣れることを目標にしてください。次回は、Claude Codeに「覚えさせる」仕組みであるCLAUDE.mdについて説明します。

#### 記事5：CLAUDE.mdって何？「覚えさせる」基本の仕組み

Claude Codeを使い始めると、必ずと言っていいほど出てくるのが「CLAUDE.md」というファイルです。今回は、この仕組みの基本を説明します。

**CLAUDE.mdとは**

CLAUDE.mdは、プロジェクトのフォルダ（またはその中の`.claude`フォルダ）に置く、ごく普通のテキストファイル（マークダウン形式）です。Claude Codeは、セッションを開始するたびにこのファイルを自動的に読み込みます［確認済み事実、出典：Anthropic公式ドキュメント、確認日2026-08-11］。

つまり、「毎回同じことを説明し直す」代わりに、あらかじめCLAUDE.mdに書いておけば、Claude Codeがそれを踏まえて動いてくれる、という仕組みです。公式ガイドでは、次のようなときにCLAUDE.mdへの追記を検討するとよいとされています［確認済み事実、出典：同上］。

- 同じ間違いを2回目もしたとき
- 前回のセッションで打ち込んだのと同じ訂正を、また打ち込みそうになったとき
- 新しく関わる人にも同じ説明が必要になりそうなとき

**auto memory（自動メモ）との違い**

Claude Codeには、CLAUDE.mdとは別に「auto memory（自動メモ）」という仕組みもあります。CLAUDE.mdは「人が書く指示・ルール」であるのに対し、auto memoryは「Claude自身が作業の中で学んだことを書き留めるメモ」という違いがあります［確認済み事実、出典：同上、確認日2026-08-11］。今回はまず、自分で書き込むCLAUDE.mdの使い方を押さえておけば十分です。

**基本の書き方の型（貿易実務者向けの記入イメージ）**

CLAUDE.mdに決まった書式はありませんが、見出しと箇条書きで整理すると読み込ませやすいとされています［確認済み事実、出典：同上］。貿易・海外展開実務での記入例として、次のような型が考えられます（あくまで一例であり、実際の内容は業務に合わせて記入してください）。

```
# プロジェクトの基本ルール

## この業務について
- （例）海外バイヤー向けの見積書・案内文の下書きを作るためのフォルダです

## 用語・表記のルール
- （例）社名は「株式会社◯◯」で統一する
- （例）金額は税抜表示を基本とする

## いつも気をつけてほしいこと
- （例）実在の顧客名・金額は仮の値に置き換えてから作業する
```

**自動生成もできる**

ゼロから書くのが大変な場合は、`/init`というコマンドを使うと、Claude Codeがフォルダの中身を分析して、CLAUDE.mdのたたき台を自動生成してくれます［確認済み事実、出典：同上、確認日2026-08-11］。まずは`/init`で作らせてみて、そこから自分の業務に合わせて手直ししていくのが取り組みやすい進め方です。

#### 記事7：つまずきやすいポイントと対処法

ここまで実際にClaude Codeを触ってみると、思ったとおりに進まない場面も出てくると思います。今回は、実務者がつまずきやすいポイントと、その対処の型を紹介します。

**つまずき1：インストールコマンドがうまく動かない**

Windowsでは、PowerShellとコマンドプロンプト（CMD）で入力するコマンドが異なります。PowerShell用のコマンドをCMDで打つと動かず、逆も同様です。公式のトラブルシューティングでも、「`&&`という記号がエラーになる場合はCMDではなくPowerShellを使っている」「`irm`が認識されない場合はPowerShellではなくCMDを使っている」といった見分け方が案内されています［確認済み事実、出典：Anthropic公式ドキュメント、確認日2026-08-11］。まず自分がどちらの画面を開いているかを確認してください（プロンプトの表示が`PS C:\>`ならPowerShell、`C:\>`だけならCMDです）。

**つまずき2：ログインできない・アクセスできないと言われる**

無料のClaude.aiアカウントだけではClaude Codeは利用できません［確認済み事実、出典：同上］。有料サブスクリプション（Pro／Max／Team／Enterprise）またはClaude Consoleアカウントでログインしているか確認してください。

**つまずき3：指示した内容と違う結果になる**

「直して」「まとめて」のような曖昧な指示は、期待と違う結果になりやすい傾向があります。「何を」「どのように」変えてほしいかを、もう少し具体的に伝え直してみてください。それでも改善しない場合は、一旦`/clear`で会話をリセットしてから、指示を出し直すのも有効な方法です［仮定：改善の度合いは状況によるため断定はしません］。

**つまずき4：CLAUDE.mdに書いたのに反映されている気がしない**

CLAUDE.mdの内容がきちんと読み込まれているかは、セッション中に`/context`というコマンドで確認できます［確認済み事実、出典：同上、確認日2026-08-11］。一覧の中にCLAUDE.mdが表示されていない場合は、ファイルの置き場所（プロジェクトのルート、または`.claude`フォルダの中）を見直してください。

**つまずき5：CLAUDE.mdがどんどん長くなってしまう**

CLAUDE.mdは短く具体的に書くほど、指示として読み込まれやすいとされ、目安として200行程度に収めることが推奨されています［確認済み事実、出典：同上］。内容が増えてきたら、本当に毎回必要な情報かを見直し、思い切って整理することをおすすめします。

**心構えとして**

最初から完璧に使いこなそうとせず、小さな指示から試して、うまくいかなかったときに「どこが曖昧だったか」を振り返る、という進め方が現実的だと感じています。ここまでの7本で、Claude Codeを実務の中で触ってみるための基本は一通りお伝えしました。次回は、ここまでの内容を踏まえて、次のステップをご案内します。
