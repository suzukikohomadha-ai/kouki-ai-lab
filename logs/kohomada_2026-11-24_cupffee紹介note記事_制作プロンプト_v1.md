# 依頼：Cupffee社を紹介するコホマダnote記事の制作（リサーチ・本文・図解画像まで一括）

## 0. ゴールと前提

株式会社コホマダのnoteに、Cupffee（https://cupffee.me/en ）の会社とサービスを紹介する記事を掲載したい。
今回の作業範囲は「リサーチ → 記事本文 → 図解・表の画像作成 → 監査」まで。**noteへの投稿・Cupffee社への連絡は行わない**（投稿は社長が行う）。

記事の目的（優先順）：
1. **問い合わせ獲得**：Cupffee製品の卸先（導入を検討する事業者）からコホマダへ問い合わせをもらう
2. **卸先開拓**：どんな業種・シーンで使えるかを具体的に示し、卸先候補に「うちでも使える」と思わせる
3. **ブランディング**：コホマダが海外メーカーと国内事業者をつなぐ人脈・ネットワークを持っていることを伝える

## 1. 社長からの前提情報【社長記入】

- コホマダとCupffee社の関係：【社長記入：例）日本総代理店契約済み／代理店交渉中／紹介のみで契約なし／不明】
- 記事で公開してよい卸条件（最低ロット・価格帯・サンプル提供の可否等）：【社長記入 or「非公開」】
- 人脈・実績として書いてよい具体的事実（取引国数・業種・紹介実績等。数字は事実のみ）：【社長記入 or「なし」】

上記が空欄の場合は、**作業開始前にまとめて1回だけ質問**し、回答が得られない項目は記事内で断定せず `[要ヒアリング]` のプレースホルダにする。
特に「代理店」「正規販売店」「日本独占」等の表現は、社長が関係を明示しない限り使わない。

## 2. 体制と参照ルール（層Aのルーティング）

ジン（jin-chief-of-staff）が統括し、以下の順で必要な社員だけを使う：

| 順 | 担当 | 役割 |
|---|---|---|
| 1 | リサ（lisa-research-analyst） | Cupffee社・製品・市場の一次情報調査 |
| 2 | サトル（satoru-growth-strategist）＋レン（ren-business-strategist） | 想定卸先の業種整理・記事構成・CTA設計 |
| 3 | 作成担当（秘書／ジン配下で執筆） | 本文執筆 |
| 4 | カエデ（kaede-creative-director） | 図解が必要な箇所の分析・図解の構成指示 |
| 5 | ノヴァ（nova-web-3d-engineer） | HTML/SVG → PNG のレンダリング実装 |
| 6 | アオイ（aoi-quality-auditor） | 本文＋全画像の独立監査（**省略不可**） |

着手前に必ず読む：
- `.claude/skills/kohomada-business-context/`
- `.claude/skills/market-research-protocol/` `.claude/skills/fact-check-and-citations/`
- `.claude/skills/copywriting/` `.claude/skills/sns-operation/`
- `.claude/rules/evidence-policy.md` `external-publication-policy.md` `approval-policy.md` `content-draft-automation.md` `file-naming.md`
- 過去のnote関連成果物：`logs/kohomada_*note*` （トーン・マガジン構成・過去の監査指摘を踏襲する。特に2026-07-28の「出典URLの中身と本文が食い違った」失敗を繰り返さない）

まず `logs/` に Cupffee関連の既存記事（ファイル名・本文に cupffee／カップフィー を含むもの）があるか確認する。
- **既存記事がある場合**：本文は書き直さず、その記事を土台に STEP 4（図解分析）から実施。ただし事実部分は STEP 1 の調査で裏取りし、食い違いがあれば修正案を出す。
- **無い場合**：STEP 1 から全工程を実施する。

## 3. 作業手順

### STEP 1：リサーチ（リサ）

調査対象（一次情報を最優先。https://cupffee.me/en の全ページ＝About・Products・FAQ・B2B/Wholesale・Contact・ニュース等を実際に開いて読む）：

- 会社概要：正式社名・所在国・創業年・創業者・沿革・ミッション
- 製品：ラインナップ（サイズ・容量・種類）、原材料、耐熱/耐冷・使用可能時間などの仕様、賞味期限、保存方法、アレルゲン表示
- 特徴・差別化：環境面の主張（プラ/紙カップとの比較）、食べられることの価値、認証・受賞歴
- B2B情報：卸・OEM・カスタムロゴ印刷の有無、最低ロット、輸出実績・取扱国
- 導入事例：カフェ・航空会社・イベント・ホテル等の公表事例（公式発表または信頼できる報道に限る）
- 日本市場：日本での販売実績・既存代理店の有無、食品輸入（食品衛生法上の手続き等）に関わる論点 → 法的論点はリョウに渡す前提で `[要確認]` として列挙のみ
- 市場背景：使い捨てプラスチック規制・エディブルカップ市場の動向（官公庁・国際機関・信頼できる調査機関のみ）

記録ルール：
- 事実ごとに「出典URL／発行主体／公開・更新日／確認日（2026-11-24）」を表で記録
- `[確認済み事実]` `[未確認]` `[要追加調査]` `[要ヒアリング]` を必ず付ける
- 公式サイトの宣伝文句（"100% eco-friendly"等）は「同社は〜と説明している」と主語を明示して扱い、第三者事実として断定しない
- 数値・認証・事例は、出典ページ本文に実際に書かれていることだけ採用（タイトル一致で済ませない）
- 保存先：`logs/kohomada_2026-11-24_Cupffee調査_v1.md`

### STEP 2：記事設計（サトル＋レン）

- 想定読者（卸先候補）を3〜5業種に絞る（例：カフェ・ベーカリー／ホテル・旅館／イベント・展示会運営／企業のサステナビリティ施策・ノベルティ／自治体・観光施設 等。調査結果に根拠がある順で）
- 業種ごとに「導入メリット」「想定シーン」を1行で整理
- CTAを設計：問い合わせ導線（コホマダの問い合わせ先 `[要ヒアリング：URL/フォーム]`）、問い合わせ時に書いてほしい項目（業種・想定数量・用途・希望時期）
- ブランディング要素：「海外の優れたプロダクトを日本の事業者につなぐコホマダ」という立ち位置を、誇張せず事実ベースで1段落にまとめる（人脈の数値は社長提供の事実のみ）
- note マガジンは「貿易・海外展開」を基本（変更する場合は理由を記載）
- 見出し構成案（H2/H3）と、各見出しの狙いを先に出す

### STEP 3：本文執筆

- 文字数目安：4,000〜6,000字。です・ます調、専門用語には一言説明
- 構成の目安：
  1. リード（課題提起：使い捨てカップ問題・差別化に悩む店舗/企業）
  2. Cupffeeとは（会社概要）
  3. 製品の特徴（仕様・強み）
  4. 従来カップとの比較
  5. こんな事業者におすすめ（業種別の活用シーン）
  6. 導入までの流れ（問い合わせ→サンプル→見積→発注→納品。ただし社長が確認できていない工程は `[要ヒアリング]`）
  7. コホマダについて（海外メーカー×国内事業者をつなぐ役割・ネットワーク）
  8. お問い合わせ（CTA）
  9. 参考情報（出典一覧）
- 画像を入れる位置に `【図解①：タイトル】` のようにマーカーを入れる
- 禁止：「必ず売れる」「地球にやさしい唯一の〜」等の断定・最上級表現、未確認の価格・ロット・事例、競合他社の誹謗、Cupffeeの公式画像・ロゴの無断転載
- 景品表示法（優良誤認）・食品表示に触れうる表現はリョウに確認依頼のリストを作る
- 保存先：`logs/kohomada_2026-11-24_Cupffee紹介note記事_本文_v1.md`

### STEP 4：図解・表が必要な箇所の分析（カエデ）

本文を読み、「テキストだけでは分かりにくい箇所」を次の基準で洗い出す：

| 判定基準 | 向いている図の型 |
|---|---|
| 3項目以上を複数の軸で比べている | 比較表 |
| 手順・時間の流れがある | フロー図（ステップ） |
| 登場人物・会社が3者以上関わる | 関係図（商流図） |
| 数値の大小・推移を語っている | グラフ（出典のある数値のみ） |
| 業種×シーンの組み合わせ | マトリクス／カード一覧 |
| 一言で魅力を伝えたい | 特徴まとめ（アイコン＋短文3〜4点） |

出力：「図解候補リスト」表（No／挿入位置の見出し／分かりにくい理由／図の型／載せる情報／出典）。
その中から**効果の高い4〜7点**を選び、選定理由を書く。想定例（本文次第で入れ替えてよい）：
- 図解①：Cupffeeとは？ひと目で分かる製品概要（特徴まとめ）
- 図解②：従来の紙カップ・プラカップ・Cupffeeの比較表（比較軸は出典で裏付けられる項目のみ）
- 図解③：業種別の活用シーン（マトリクス）
- 図解④：商流図（Cupffee → コホマダ → 卸先 → エンドユーザー）※関係性は社長確認済みの範囲で描く
- 図解⑤：導入までの流れ（ステップ）
- 図解⑥：問い合わせ時に伝えてほしい項目（チェックリスト型CTA）

### STEP 5：画像の制作（カエデ構成 → ノヴァ実装）

制作方式：HTML＋CSS（必要に応じてインラインSVG）で各図解を作り、プリインストール済みの Playwright（Chromium）でPNGに書き出す。Canva MCPが認証済みで使える場合のみ、Canva案を追加で出してもよい（必須ではない）。

画像仕様：
- サイズ：横1280px基準（比率は図に応じて 1280×670／1280×960 等）、`deviceScaleFactor: 2` で書き出し
- フォント：日本語ゴシック（Noto Sans JP が使えなければ IPAゴシック）。本文最小 24px相当、スマホで読める文字サイズ
- 配色：コホマダのトーン（落ち着いた信頼感）＋製品テーマのアクセント（例：コーヒーブラウン・クリーム・環境を示すグリーン）の3〜4色に統一。全画像で同じデザインシステムを使う
- 1枚1メッセージ。情報を詰め込みすぎない（1枚あたり要素7個程度まで）
- 各画像の下部に小さく出典（例：「出典：Cupffee公式サイト（2026-11-24確認）」）とコホマダ表記
- Cupffeeのロゴ・製品写真・他社の画像は使わない（自作アイコン・図形・テキストのみ）。社名はテキスト表記
- 数値・仕様は STEP 1 の調査ファイルにあるものだけ。未確認の値は図に入れない

保存先：
- HTMLソース：`logs/images/kohomada_2026-11-24_cupffee/src/図解01_<件名>.html` …
- PNG：`logs/images/kohomada_2026-11-24_cupffee/図解01_<件名>.png` …
- 書き出し後、全PNGを自分で開いて目視確認（文字切れ・はみ出し・誤字・重なり）し、問題があれば直してから次へ

### STEP 6：監査（アオイ・省略不可）

アオイに本文・調査ファイル・全PNGを渡し、以下を確認させる：
- 出典URLの**中身**と本文・図解の記載が一致しているか（実際にページ内容と照合）
- 事実／推測／提案の区別、断定・最上級表現、景表法・食品表示上の懸念
- コホマダとCupffeeの関係性の書き方が社長確認済みの範囲を超えていないか
- 図解内の数値・用語が本文と一致しているか、誤字・文字切れ
- 問い合わせCTAに `[要ヒアリング]` が残っていないか（残っていれば一覧化）

判定が `REVISE` なら修正して再監査。`PASS` / `PASS WITH CONDITIONS` になるまで繰り返す。
監査結果は `logs/kohomada_2026-11-24_Cupffee紹介note記事_監査_v1.md` に保存。

### STEP 7：仕上げ

- 本文に、図解マーカーと対応するPNGファイル名を明記した最終版を作る（修正があれば `_v2` で新規保存、旧版は残す）
- 「📝コンテンツ下書き・DB」への登録は、社長が希望した場合のみ（`content-draft-automation.md` の規約どおり：事業=コホマダ／媒体=note／種別=無料／マガジン=貿易・海外展開／下書き作成済み=__YES__、本文末尾に免責文言）
- `office/state.js` に本件タスクを起票し、完了時は `status:"review"` で決裁トレイへ

## 4. 最終報告の形式

秘書アイの声で、次の順に簡潔に報告する：
1. 結論（記事と画像◯点ができた／監査判定）
2. 成果物一覧（ファイルパス）
3. 画像一覧（No・挿入位置・何を伝える図か）
4. 未確認事項・`[要ヒアリング]` 一覧（社長に確認してほしいこと）
5. **社長の承認が必要な事項**：note投稿、Cupffee社名・製品名の記事掲載に関する先方確認の要否、卸条件の公開可否、問い合わせ先の確定
6. 次の一手（番号付きで最大3つ）

## 5. 絶対にやらないこと

- noteへの投稿・公開、Cupffee社やその他外部への連絡・送信
- 調査で確認できなかった会社情報・価格・ロット・認証・導入事例・統計の創作
- コホマダの人脈・実績の数値の誇張・創作
- 他社の画像・ロゴの無断使用
- 実行していない工程を「完了」と報告すること

## 補足（このプロンプトの設計意図）

| 工夫 | 理由 |
|---|---|
| 冒頭で「関係性・卸条件・人脈の事実」を社長に確認させる | 「代理店」表現や人脈の数字は記事の信頼性と法的リスクに直結し、AIが推測で書くと危険なため |
| 既存記事の有無で分岐 | 「既に作成した記事に挿入する画像」という依頼にも、ゼロからの依頼にも1本で対応するため |
| 図解の判定基準表を明示 | 「どこが分かりにくいか」をAIの感覚任せにせず、比較・手順・関係・数値・組み合わせの5パターンで機械的に洗い出させるため |
| HTML→Playwright でPNG化 | 日本語の文字化け・崩れが起きにくく、修正も文字の書き換えだけで済む。この環境にPlaywrightとIPAフォントが入っていることを確認済み |
| 監査で「出典URLの中身」まで照合 | 2026-07-28のnote記事で、タイトルは合っているが中身が食い違う誤りが3件見つかった経緯を反映 |
| 投稿・外部連絡を明示的に禁止 | approval-policy／external-publication-policy に準拠 |
