# 招待リンク（population A/B識別）の導入手順

- 基準日：2026-08-25
- 担当：ジン（AI Chief of Staff）／秘書アイ
- 依頼元：社長「B13（招待リンクの最小実装）から着手」（矛盾点・不足情報整理v1のB13対応）
- 成果物：`scripts/invite-link-gate.gs`

---

## 結論

1. Discordは現行A案（固定投稿、Gateway常時接続なし）のため、入室イベントそのものからのpopulation識別はできない。LINEも標準のMessaging APIには入口別の識別情報は乗らない。
2. そこで、`kit-download-gate.gs`と同じ「Google Apps Script＋自動生成スプレッドシート」パターンを流用し、**リンクを踏んだ時点でクリックを記録してから、実際の入会先へ移動する**という最小の仕組みを作った（UTMパラメータ相当）。
3. これは「クリックした」ことの記録であり、「実際にDiscord/LINE/noteへの入会まで完了したか」までは追跡していない（クリックログのみ、最小実装のため）。より正確な追跡は将来の拡張課題とする。

---

## 導入手順（社長ご自身の操作）

1. [script.google.com](https://script.google.com) にアクセスし、「新しいプロジェクト」を作成する（既存のスターターキット配布プロジェクトとは**別プロジェクト**として作成することを推奨）。
2. `scripts/invite-link-gate.gs` の中身を全文コピーし、エディタに貼り付けて保存する（プロジェクト名は任意、例：「招待リンクゲート」）。
3. スクリプト冒頭の `DESTINATIONS` を、実際のURLに書き換える。
   ```
   const DESTINATIONS = {
     discord: 'https://discord.gg/実際の招待コード',
     line: 'https://lin.ee/実際のID',
     note: 'https://note.com/実際のURL',
   };
   ```
   Discordの招待リンクは、Discordアプリのサーバー設定→「招待」から、**有効期限なし・使用回数無制限**の招待リンクを1つ発行して使う想定（既存のBot権限だけで作れる、鈴木さんの操作）。
4. 画面右上の「デプロイ」→「新しいデプロイ」を選択。
   - 種類の選択：「ウェブアプリ」
   - 実行するユーザー：「自分」
   - アクセスできるユーザー：「全員」
   - 「デプロイ」をクリック
5. 初回は「このアプリは Google で確認されていません」の警告が出る（自分が作成したスクリプトなので問題ない）。「詳細」→「（プロジェクト名）に移動」→「許可」と進む。
6. 発行された「ウェブアプリのURL」（`https://script.google.com/macros/s/.../exec`）をコピーする。
7. **必ずご自身で動作確認する**（本エージェントはApps Scriptの実行環境を持たないため、実際に動くかどうかの最終確認はできていない）。
   - `<URL>?src=A&dest=discord` を開き、実際にDiscordへ移動するか
   - `<URL>?src=B&dest=discord` も同様に確認
   - `<URL>?action=stats` を開き、クリック数の集計表が表示されるか

## 実際の使い方

| 用途 | リンクの形 |
|---|---|
| population A（既存商談で費用感・資金不足を理由に流れた案件へのフォローアップ） | `<URL>?src=A&label=<案件名や社名など任意メモ>` |
| population B（note記事・X投稿等の公開マーケ経由） | `<URL>?src=B` |

`dest`パラメータで移動先を切り替えられる（省略時はDiscord）。例：`<URL>?src=B&dest=note`

**個別のpopulation Aリード宛てにこのリンクを送る操作自体は、社内の承認フローに従い、送付前に社長の確認を経てください**（本スクリプトの作成・デプロイ準備までが本タスクの範囲であり、実際に個別の相手へ送付する判断は含みません）。

## リスク・注意点

1. **【要実機確認】** 本スクリプトは作成のみで実行環境がないため動作未確認。社長ご自身によるテストを必須とする。
2. **（軽微）** クリックログはあくまで「リンクを踏んだ」記録であり、実際の入会完了は別途Discord/LINE/noteの管理画面側で確認する必要がある（クリック数と入会数は一致しない）。
3. **（軽微）** `label`欄は任意の自由記述であり、個人情報（実名等）を直接書き込まないよう運用上の注意が必要（[[.claude/rules/personal-data.md]]相当の配慮。案件ID・仮称での記録を推奨）。
4. **（中程度）** 現状は`src=A`/`src=B`の2値のみの粗い識別であり、v5前提条件1（情報管理シートの概算カウント）が指摘した「実データでの検証」を完全に代替するものではない。今後この仕組みで蓄積されるクリックログが、初めての実データとなる。

## 次に必要なアクション

- 社長へ：上記手順1〜7の実施、DESTINATIONSの実URL設定、動作確認
- ジンへ：URL発行後、note/Discord/LINE運用の各所（今後の個別フォローアップ・公開投稿）でこのリンクを使うよう、既存の実行計画（`kohomada_2026-08-02_新サービス構想_導線設計X-note-Discord-LINE-BOOTH_v1.md`等）に反映
- 一定期間（例：1ヶ月）運用した後、`?action=stats`の集計結果を事業計画書の次版に反映し、population A主戦力説の検証材料とする
