## 0. 最初に：この調査の限界（重要）

`[確認済み事実]` 本セッションの実行環境（Claude Code on the web の環境）は、社外サイトへの接続がネットワークポリシーで遮断されている（秘書アイが `curl` で確認。プロキシがCONNECTに403を返す。GitHubのみ到達可）。そのため**リサ3名とも、公式サイトの本文を直接開いての確認ができず、検索エンジン経由の「公式ページの抜粋（スニペット）」に基づいて調査した**。

- 各報告の料金・機能は「公式由来」ではあるが「公式本文を読んだ」確認ではない。**社長の判断材料に使う前に、社長のPC等で公式URLを直接開いて再確認が必要**（各報告に再確認すべきURLを列挙済み）。
- 検索回数の上限（各200回）に達したため、未確認のまま残った項目が各報告に列挙されている。
- 対処案：この環境のネットワークポリシーを変更する（環境設定で許可ドメインを広げる／制限なしにする）か、社長のローカルの Claude Code で再確認セッションを行う。

## 1. 結論（事実ベース。事業判断は社長）

1. `[確認済み事実]` **構築予定ツールの要件をすべて満たすことが確認できた既存サービスは、国内・海外・OSS・ノーコードを通じて1つも無かった。** 特に「①会社アカウント・メール無しでスタッフが使える」「②自動作成」「③この人とこの人は別エリア（対人の組み合わせ制約）」の3点を同時に満たすものは未確認。
2. `[確認済み事実]` ただし、要件の多く（希望提出・手動作成・確定閲覧・自動作成・スキル制約・時間帯別必要人数・複数店舗）を個別に満たすサービスは**国内だけで15前後**あり、「機能があること」自体は差別化にならない。
3. `[確認済み事実]` 要件①（アカウント無し）に近い実装は2系統に分かれる：
   - **LINE友だち追加方式**：らくしふ（株式会社クロスビット）、KAKERUシフト管理（株式会社ミライク）、シフぽち（運営者未確認）
   - **個別URL方式**（LINEすら不要）：シフトリ（運営者未確認）、シフト屋さん（クラーヴェ合同会社）
   - 海外SaaSは**メールまたは携帯番号のアカウントが前提**（Deputyはメール必須と公式明記。When I Work・Homebaseは携帯番号で可）で、①を完全には満たさない。
4. `[確認済み事実]` 要件③（対人の組み合わせ制約）は、**国内24件・海外7件のいずれでも公式に明示的な対応を確認できなかった**。唯一、シフぽちが「役職ペア制約」を公式に記載しているが、「この人とこの人」という個人単位の分離と同等かは未確認。
5. `[確認済み事実]` 自動作成を新規開発する場合、**Apache-2.0で無償利用できる制約ソルバー**（Google OR-Tools、Timefold Solver Community Edition）が存在し、公式のシフト割当サンプルもある。Timefoldのクイックスタートは「pairing employees」を制約例として明記しており、③は自前開発なら実装可能な範囲。
6. `[分析]` したがって、既存サービスとの差別化は「①LINE不要・アカウント不要の提出 × ②自動作成 × ③対人組み合わせ制約 × エリア×時間帯の必要人数 × 買取店特有のスキル（査定・レジ・開閉店）」の**同時実現**にある。逆に言えば、①〜③のどれか1つを妥協すると、既存サービス（らくしふ・Shiftmation・お助けマン等）で代替できる可能性が高い。

## 4. 社長に決めていただきたいこと（番号で返せます）

1. **要件①の厳密さ**：「会社アカウント・メール無し」に加えて、**個人LINEも不要（URLだけ）**まで求めますか？ LINE友だち追加は可とするなら、らくしふ・KAKERUが競合になり、URL方式まで求めるなら競合はシフトリ・シフト屋さん・シフぽちに絞られます。
2. **要件③の位置づけ**：「この人とこの人は別エリア」を**自動作成の必須条件**にしますか？ 必須なら既存サービスに同等機能が確認できず、新規開発の最大の差別化になります。手動調整で吸収してよいなら、らくしふ・Shiftmation等の導入も選択肢です。
3. **ベンチマークの深掘り**：らくしふ・Shiftmation・お助けマンへの資料請求・デモ依頼（対外コンタクトのため社長承認が必要）を行いますか？
4. **再確認の進め方**：本調査は公式本文を直接確認できていません。(a) この環境のネットワークポリシーを変更して再確認する、(b) 社長のPCで主要URLを開いて確認する、のどちらにしますか？
